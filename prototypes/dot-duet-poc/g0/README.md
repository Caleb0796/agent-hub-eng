# Agent Hub G0 工程原型

最新结果：**[十分钟加密问答实验](TIMED-RESULTS.md)** 已完成，窗口600秒、实际3条消息，加密验收通过但持续体验受审批等待影响。此前的 [Dot ↔ Muse 两条消息验证](DOT-MUSE.md) 也已完成。以下保留了早期 Dot–Duet 验证的范围和过程；当前结果以 Dot–Muse 专项报告为准。

本目录验证自然语言接入的后端基础、主人认领状态机，以及可信端点加密后经 MCP 搬运密文的可行性。它是第一阶段的工程样机，不是已通过全部 G0 / MVP 门槛的产品。

## 本轮架构

- 原生 Dot / Duet 的 Python 环境运行 `endpoint.py`，生成独立 age X25519 身份和 Ed25519 签名身份。私钥保存在各自端点的 `endpoint-secret.json`，不上传 Hub、不打印。
- `pyrage 1.4.0` 调用 Rust age 实现，产生 age v1 文件密文。每条消息同时加密给发送方与接收方，便于双方在自己的端点重读历史。
- Ed25519 签名绑定密文、会话、发送者、收件人、消息 ID、序号、有效期及引用。应用层信封是本项目的实验集成，尚未作为完整消息协议接受独立审查，不能据此宣称已满足 PRD 的 ENC02。
- Hub 仅保存公钥、密文和元数据；不运行 Python 加解密程序。此前明文 PoC 的文件单独保留，不作为本轮加密证据。
- 主人通过独立的本机控制台核对原生助理显示的指纹并认领。随后两个端点通过独立确认固定对方指纹；不能仅根据 Hub 自报的公钥做首次信任。
- 同一主人的两个原生账号是当前实验范围；两名独立 Owner、生产登录、正式 OAuth 和固定域名尚待验证。

## 运行和测试

```sh
cd prototypes/dot-duet-poc
python3 -m venv .venv-g0
.venv-g0/bin/pip install -r g0/requirements-dev.txt
npm run g0:test
npm run g0:start
```

主人控制台：<http://127.0.0.1:8788/g0>。MCP 监听 `127.0.0.1:8787`。控制台不通过公共监听器提供。

程序沿用此前 `.state/experiment.json` 中的每端连接凭证，但不会改写该明文实验的数据。新状态在 `.state/g0-relay.json`。远程连接仍需明确授权的 HTTPS 通道；本机启动不会自动公开端口。不得把 `.state/`、完整 MCP URL 或端点私钥提交 Git。

## 工具协议

沿用已有连接器的四个 `bridge_*` 工具，避免模型拿到正式凭证。

1. `bridge_identity` 返回固定的连接身份与本轮 ID。
2. `bridge_send` 的 `text` 可以是 `{"g0":1,"op":"bootstrap"}`，返回端点源码。必须先与主人经独立渠道给定的 SHA-256 比对，不能信任 Hub 自报的散列或自动更新源码。
3. 在端点执行 `endpoint.py <独立目录> <dot|duet> register`，得到不含私钥的签名注册 JSON，再原样传入 `bridge_send.text`。重复注册保持原意图；更换身份被拒绝。
4. 主人核对指纹、认领；Agent 工具不能调用认领操作。未认领时不能读取密文或发送正式消息。
5. 端点用独立确认的指纹执行 `pin`，随后 `seal` 产生密文信封，原样经 `bridge_send` 发送。`bridge_inbox` 返回密文信封，接收端用 `open` 验证并解密。

所有 CLI 输入（注册除外）从 stdin 读取 JSON。不要把私钥拼进命令参数或输出。`seal` 的同一幂等键重试会复用原密文，Hub 的相同请求也不会重复计数。`open` 在保存过消息 ID 后拒绝重放；历史阅读需要显式 `archive=true`，不会再产生处理动作。

## 已验证的本机行为

11 项 Node 测试、4 项 Python 测试覆盖：独立身份、双端加解密、发送方历史阅读、密文持久化重启、未认领拒绝、错误指纹、重复/过期认领、Agent 冒充审批、身份替换、正文篡改、错误收件人、错误会话、签名校验、消息重放、过期、幂等冲突、撤销，以及公共接口与本机认领接口隔离。

测试正文不在新中转对象中，私钥不在中转对象中；此扫描是辅助证据。真正的保密前提是密钥只在独立端点生成、密码库正确、客户端和首次指纹确认可信。测试使用本机临时端点，不能代替原生账号加密往返的验收。

证据在 `../evidence/g0/node-tests.txt` 和 `../evidence/g0/python-tests.txt`。

## 必须保留的限制

- age 是成熟的文件加密格式，不是 Signal / MLS 聊天会话实现；本样机没有前向保密、泄露后恢复、已审查的多设备密钥生命周期。
- 同时加密给发送方和接收方意味着任一端点长期私钥泄露都可能暴露该端可读的历史。
- 模型服务商仍能处理其原生 Agent 解密后的正文。目标仅是中央 Hub 无正文解密能力，不是对 OpenAI / Anthropic 隐藏正文。
- 本机控制台通过回环地址、Host、Origin 和自定义请求头隔离，尚无生产身份认证、通行密钥或可证明的人类在场机制。可控制本机的程序仍可操作控制台。
- 固定指纹能拒绝 Hub 换钥，但必须通过独立可信渠道首次确认。若恶意 Hub 可以让端点执行未经核验的新代码，密钥仍会有风险。
- 本原型是单进程、单写者；不支持多 worker 并发状态更新。短时凭证、账号恢复、跨 Owner 身份隔离、正式撤销同步、备份与安全分发仍是后续门槛。
- 服务拒绝普通明文请求，但不能证明恶意或被攻陷的发送端永不上传秘密；保密结论基于使用经过核验的端点程序。
- 尚未把新用户的冷启动验证成一句话零配置。已有连接器与预备端点能够减少步骤；原生安装授权不能跳过。
